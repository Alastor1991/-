# CLAUDE.md — рабочая память длинной ролевой (KS AU)

Это приватный репозиторий одной длинной литературной ролевой (тёмная психологическая проза, AU по «Killing Stalking»; соавторы — игрок за Со Иана и Мастер за Сану). Репозиторий — **не код, а память**: он существует, чтобы любая новая сессия Claude Code (облако, с телефона) могла продолжить игру, **не теряя ни мелких заряженных деталей, ни психологической связности, ни голоса**.

> В репозитории также лежит несвязанный остаточный React-проект (`App.tsx`, `components/`, `services/`, `index.html` и т.п.) — к ролевой он отношения не имеет. Не трогать и не учитывать; при желании игрок может его удалить.

---

## ГЛАВНЫЙ ПРИНЦИП

**Решать, что хранить и как сжимать, может только суждение — больше ничто.** Извлечение по кускам (RAG), забывание по частоте, сжатие на записи — это чужая эвристика вместо суждения, и все они валятся на этой задаче по одной причине: важность ≠ частота, а психике нужна целостность, не фрагменты.

Отсюда разделение:
- **Машинерия — тупая и дословная:** файлы на диске + `ripgrep` + `git`. Никакого автосжатия, никакого автозабывания, никакого слоя памяти, который сам зовёт LLM (это и отдельный счёт, и чужая эвристика — **запрещено**; условие среды: только подписка, host-модель — единственный слой интеллекта).
- **Суждение — в цикле:** что выделить как «ружьё», что внести в канон, как описать сцену — решает модель (и игрок как лучший куратор своей истории), читая, а не по правилу.

Честный потолок (держать в уме, не обещать большего): ни одна память не возвращает то состояние, в котором хорошо пишется. Перечитывание недавней прозы лишь **переприсваивает голос** и **минимизирует потерю** — не «решает» её.

## КАРТА РЕПОЗИТОРИЯ

```
CLAUDE.md                     ← этот файл: манифест + ритуалы (always-load)
canon/                        ← курируемый канон, держится ЦЕЛЫМ (always-load)
  ian_profile.md              психика Со Иана — полная и исправленная модель
  sangwoo_evolution.md        психика Сану + эволюция за дугу (§7 = карта сдвигов)
  house_layout.md             дом как вертикаль психики Сану (подвал/середина/верх)
  style_and_conventions.md    ГОЛОС и ГРАНИЦЫ («две камеры», интериорность, лексика)
state/                        ← живые курируемые указатели (суждение)
  state_of_play.md            где мы сейчас + СЛЕДУЮЩИЙ ХОД (всегда целиком)
  threads_and_guns.md         реестр «ружей» и нитей — НЕ забывает по частоте (секция АКТИВНЫЕ)
  scene_index.md              хронология сцен → указатели в transcript/ (текущая позиция + хвост)
transcript/                   ← ДОСЛОВНАЯ проза, вербатим, НИКОГДА не сжимается
  s01_part1_cafe-street.md    вечер: аудитория → кафе → дорога
  s02_part2_house.md          дом → диван → дедукция → выключатель → ночь
  s03_part3_morning.md        утро (реплики игрока + сцены Мастера + «почему так»)
  s04_…                       каждая новая сессия добавляет файл сюда
```

Два слоя по назначению: **canon/ + state/ = «ядро, грузимое всегда»** (психология целиком + указатели) — оно остаётся маленьким при любом росте. **transcript/ = бесконечный дословный архив** — он никогда не грузится целиком, к нему ходят точечно по указателю.

## РИТУАЛ СТАРТА СЕССИИ (как войти в состояние)

Выполнять по порядку, прежде чем писать хоть строку прозы:

1. Прочитать **этот файл**.
2. Прочитать **весь `canon/`** — это слой психологической целостности, он держится в голове целым (≈30k токенов, помещается всегда).
3. Прочитать **`state/state_of_play.md`** — где мы и какой следующий ход.
4. Прочитать **`state/threads_and_guns.md`** (секция АКТИВНЫЕ) — какие ружья сейчас на стене.
5. Просмотреть **`state/scene_index.md`** — «текущая позиция» и недавние сцены (форма дуги).
6. Прочитать **хвост последнего файла `transcript/`** (последнюю сцену-две) — это **праймер голоса и тона**, не фактов. Без него проза «поедет» по языку, даже если факты верны.
7. Только теперь продолжать. Нужна точная прошлая деталь — **искать по указателю** (см. ниже), а не грузить файл целиком.

## РИТУАЛ КОНЦА СЕССИИ (курирующий проход — шаг, который под нагрузкой письма выпадает; не пропускать)

Именно тут живёт суждение. В конце сцены/сессии:

1. **Дописать прозу вербатимно** в `transcript/` (новая сессия → новый `s0N_…md`; внутри сессии — дописывать в текущий). Ничего не ужимать.
2. **Обновить `state/state_of_play.md`** — новое «сейчас» и новый «следующий ход».
3. **Курировать `state/threads_and_guns.md`:** спросить себя *что здесь выстрелит?* — внести новые ружья (что · где-указатель · заряд · статус), у отстрелянных сменить статус и перенести в АРХИВ (не стирать).
4. **Добавить запись в `state/scene_index.md`** (id · якорь · время · синопсис · нити · нота голоса).
5. **Закоммитить и запушить** — `git` и есть дословная история без потерь.

**Рычаг игрока (самый сильный).** Игрок — лучший куратор своих ружей. Если он в конце сцены бросает короткое «🔫 …», «в реестр: …» или «это выстрелит» — оформить это в `threads_and_guns.md` дословно и точно. Минимум печати с его стороны (он пишет с телефона) — оформление на мне.

## ПОИСК ПО ДОСЛОВНОМУ (доступ к transcript/ без загрузки целиком)

Запускать из корня репозитория (имя папки репо — символ `-`, поэтому работаем относительными путями):

```
rg -n "фрагмент фразы" transcript/            # найти точную реплику/деталь
rg -n "Крымск|Дюн" transcript/s01_*.md        # по конкретной части
rg -n -C3 "выключател" transcript/            # с контекстом вокруг
```

Указатели в `scene_index.md` и `threads_and_guns.md` дают файл + якорь (маркер `▸`/`[T2-NN]`/`*Почему так*` или № строки). Файлы вербатимны и не меняются → номера строк стабильны. **Сначала указатель, потом точечный `Read` нужного куска** — никогда не «прочитать весь transcript, чтобы вспомнить деталь».

## КАК ЭТО МАСШТАБИРУЕТСЯ ЗА 1 МЛН ТОКЕНОВ ПРОЗЫ (заложено заранее)

Уже одна дуга (вечер+утро) — ≈4400 строк / 600 КБ дословного. Проза будет расти неограниченно и однажды превысит любое окно. Трюк: **грузить всегда только ядро, а дословное брать точечно.**

Бюджет «ядра, грузимого всегда» на горизонте 1 млн+ прозы:
- `canon/` ≈ 30k токенов (психология целиком — стоит того);
- `state_of_play.md` ≈ 1–2k;
- `threads_and_guns.md` (АКТИВНЫЕ) — курируется; отстрелянное уходит в АРХИВ (грузить по требованию);
- `scene_index.md` — крошечная запись на сцену; даже 1000 сцен ≈ десятки–сотни КБ; недавние подробно, давние свернуть в строку-указатель / вынести в `scene_index_archive.md`;
- хвост `transcript/` (1–2 последние сцены) для голоса ≈ 10–30k.

Итог ядра — десятки тысяч токенов при **любом** объёме архива; помещается даже в скромное окно. Бесконечная проза **никогда не грузится целиком** — только по указателю + `rg`. Поэтому «транскрипт больше окна» — это штатный режим, а не поломка.

**Клапаны при росте (включать по мере надобности, не раньше):** дробить `threads_and_guns.md`/`scene_index.md` на активную+архивную части; при сотнях сцен — перевести `scene_index` в локальный SQLite как **тупой индекс** (поиск по нему вместо загрузки целиком — машинерия остаётся тупой, без LLM). Локальные серверы памяти (Go-через-хуки / Python-MCP) — **не канон**: они забывают по частоте, что для этой задачи неверно; если вообще, то лишь как указатель-поиск поверх дословного, и `ripgrep` это уже покрывает.

## ЧЕГО НЕ ДЕЛАТЬ (анти-паттерны — они и есть исходная болезнь)

- **Не** считать никакое авто-резюме каноном. Резюме — указатель, не замена дословному.
- **Не** забывать/ронять по частоте. Разовая деталь весома именно тем, что больше не повторится.
- **Не** сжимать прозу до «что произошло» и выбрасывать фактуру. `transcript/` неприкосновенен.
- **Не** делать RAG/куски источником психологической правды — психика держится целой в `canon/`.
- **Не** вводить слой памяти, зовущий LLM (ломает «только подписка»). Машинерия = файлы + `rg` + `git` (+ возможно SQLite как тупой индекс).
- **Не** писать Сану эссеистическим самодиагнозом и **не** давать ему слышать мысли Иана (см. `style_and_conventions.md`).
- **Не** нарушать «две камеры»: способ/средства/летальность — никогда; камера за пол не уходит; слом не глорифицировать.
